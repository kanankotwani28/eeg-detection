# DECISIONS

Decisions taken while building the pipeline that CLAUDE.md left open. Format: date — decision — reason.
Values marked (E) in the configs still need an EEG/clinical expert (see docs/research_architecture_plan.md §15).

| Date | Decision | Reason |
|---|---|---|
| 2026-11-25 | Build and test the whole pipeline on **synthetic** BIDS/BrainVision (TDBRAIN-layout) and EDF (Mumtaz-layout) data generated by `src/data/synthetic.py`, then stop at the phase-0 checkpoint. | TDBRAIN needs an ORCID login + DUA acceptance by the user; it is not in the container. Synthetic results are labelled SYNTHETIC in the report and dashboard and mean nothing. |
| 2026-11-25 | Python 3.11 via `uv`; CPU wheels of torch from PyPI. | Spec; the PyTorch CPU index is blocked in the build container. GPU/MPS are used automatically when present but never required. |
| 2026-11-25 | `participants.tsv` columns are resolved by alias lists (`participants_ID`/`participant_id`, `sessID`, `indication`, `diagnosis`/`formal_status`, `age`, `gender`, `BDI*`); a missing required column stops with the list of columns found. Decimal commas in age are accepted. | Column names were not verifiable without the data. |
| 2026-11-25 | Primary indication = first token of `indication` split on `/ , ; + &`. Comorbid = more than one distinct label across `indication` and `diagnosis`. Sex is stored as the raw code; its mapping (0/1) must be confirmed from the TDBRAIN descriptor. | Avoid guessing codes. |
| 2026-11-25 | Participants with missing age are excluded from the labelled pool (age range 18–65 cannot be checked). | Conservative; counted in `cohort.json`. |
| 2026-11-25 | Splits are made for **both** T1 and T2, plus a `final` split (all participants, inner 80/20) for the frozen external-test models; client assignments are precomputed for K ∈ {1,2,4,8}, IID and label-skew. | One frozen file serves every experiment, including E17 and E11. |
| 2026-11-25 | Age-band stratification uses age tertiles × label and is used only if every stratum has ≥ 5 members; otherwise label only (recorded in `splits.json`). | Spec: "if the classes allow". |
| 2026-11-25 | Label-skew repair moves participants of a class from the richest to the poorest client until each has ≥ min(5, n_c/K). | "≥5 per class per client where possible". |
| 2026-11-25 | Within-recording bad-channel interpolation: a channel is bad if its SD < 0.5 µV or its robust z-scored log-variance > 5; interpolated (spherical spline) only when ≤ 3 channels are bad; counts are logged in QC. Done after the notch and before the average reference. | Spec allows within-recording interpolation and asks for the count; the order matters because a bad channel would contaminate the average reference. |
| 2026-11-25 | Epoch cache file names carry the dataset and condition (`epochs_{dataset}_{cond}.npy`, `epoch_index_{dataset}_{cond}.parquet`) plus a `meta_*.json` with the preprocessing-config hash. Variants (`tdbrain26`, `tdbrain-ica`, `tdbrain-noref`, `…@smoke120`) get separate caches. | Several datasets/conditions coexist; stale caches are detected by hash. |
| 2026-11-25 | Participant features = mean over epochs of per-epoch log absolute band power (natural log of the Welch PSD integrated over the band). | Spec ("average per participant"). |
| 2026-11-25 | LR: `C` is chosen by inner-validation **AUC** (ties → C closest to 1); the decision threshold is then tuned on the same validation participants for balanced accuracy. The final model is trained on the training participants only (validation kept out). | Threshold-free selection avoids double-dipping the threshold; identical recipe across regimes. |
| 2026-11-25 | EEGNet early stopping uses validation BA at threshold 0.5 (weighted CE makes 0.5 sensible), ties broken by AUC; the reported threshold is tuned afterwards on validation. | Tuning a threshold every epoch would make the stopping criterion noisier. |
| 2026-11-25 | Federated LR = the same linear model in torch (2-logit form), trained with local SGD + L2 (`fl_local_epochs: 5`), FedAvg on weights. Its feature scaler is the exact pooled training mean/SD computed from client sufficient statistics. | Equivalent to the centralised scaler without sharing raw features. |
| 2026-11-25 | DP LR uses a **per-participant feature transform** (`feature_transform: participant_relative`: log band power relative to the participant's own channel mean per band, plus band levels relative to their own mean over bands, FAA unchanged) instead of a fitted scaler; E09 applies it at every ε including ∞ so the privacy cost is measured like for like. Federated LR with a pooled scaler under DP is refused in code. | A first version released the scaler statistics with a Gaussian mechanism composed into ε; with L2 sensitivity B·√77 the noise swamped the means and DP-LR collapsed to constant predictions (smoke run: BA = AUC = 0.500). The per-participant transform has no privacy cost and drops only each person's overall log-power offset. |
| 2026-11-25 | FedAvg weights: number of epochs per client (non-DP) or number of participants (DP). | Spec ("weighted by client sample size"); under DP, epochs per participant are not the privacy unit. |
| 2026-11-25 | DP: σ is calibrated so that ε (participant level, RDP, δ = 1e-5) ≤ target **assuming the client takes part in every round**; the reported ε uses the actual number of rounds each client took part in (max over clients). steps_per_round = round(local_epochs / q), q = 0.25. | Correct upper bound under client dropout. |
| 2026-11-25 | Epoch-level ε reference = the same σ and steps with sampling rate q·n_participants / n_epochs (what a per-sample accountant would report for the same expected batch). Reported only as a labelled comparison. | Spec. |
| 2026-11-25 | FedBN with GroupNorm: GroupNorm affine parameters stay local to each client; for server-side validation and test the global model carries the average of the clients' norm parameters. | The test fold is not split by client, so a single evaluated model is needed. |
| 2026-11-25 | FedProx uses Flower's FedProx strategy (μ sent in config) with the proximal term implemented in the client; server aggregation is FedAvg. | Spec. |
| 2026-11-25 | Two FL engines with identical client logic, selection and aggregation: `flower` (Flower simulation, Ray backend; default for experiments) and `inprocess` (tests and smoke runs). `tests/test_fl.py` checks they give identical weights. | Ray start-up costs ~15 s per run; the smoke pipeline must finish in < 30 min. |
| 2026-11-25 | LiRA: each model is trained on a random stratified 50% of the pool; its in-set is split 80/20 into train/val and **validation participants are excluded** from that model's evaluation (neither member nor non-member). Each model plays the target once (leave-one-out over S models). Fixed (global) variance Gaussians. | Validation participants influence early stopping only weakly; labelling them either way would blur membership. Fixed variance is recommended when S is small (Carlini et al. 2022). |
| 2026-11-25 | LiRA sanity check: among a target's non-members, a random half is relabelled "member" → AUC must be ≈ 0.5 (`sanity_auc_nonmembers_only`). | Equivalent to a target trained without any of the evaluated participants. |
| 2026-11-25 | Report statistics: CIs are computed on out-of-fold participant predictions **averaged over seeds** (probability and threshold margin), with 2,000 class-stratified bootstrap resamples; mean ± SD across folds × seeds is reported separately. | Avoids counting a participant once per seed in the bootstrap. |
| 2026-11-25 | E01 passes if, for both BA and AUC, the mean over (fold, seed) runs is within max(0.08, t₀.₉₇₅,ₙ₋₁·SE) of 0.5. | Each shuffled-label run is an independent null model; a single run (or a seed-average within a fold, which is still one random direction) can be far from 0.5 when the features have real class structure. Two earlier rules were wrong: SD across runs only (falsely stopped at BA 0.57 with 2 runs) and a seed-averaged pooled bootstrap CI (falsely stopped at AUC 0.35 while the mean over 40 runs was BA 0.49). |
| 2026-11-25 | E11 is guarded by `artifacts/results/E11_evaluated_once.json`; re-running needs `EEGFL_FORCE_EXTERNAL=1`. Final models are trained **before** Mumtaz is loaded. | "Evaluate once." |
| 2026-11-25 | E14 "26-channel ablation" = all 26 TDBRAIN EEG channels (no interpolation needed inside TDBRAIN) vs the 19-channel set. E15 = ICA (15 components, Fp1/Fp2 as EOG proxies) and no re-referencing vs default. | Interpretation of the optional ablations. |
| 2026-11-25 | E20 EEGNet is trained for a fixed 20 epochs without early stopping inside within-Mumtaz CV. | No separate validation participants in a 64-person set; it is a sanity comparison only. |
| 2026-11-25 | MLflow uses a local SQLite store at `mlruns/mlflow.db` with artifacts under `mlruns/artifacts/`. Re-running a configuration supersedes the older run (latest per run name is exported). | MLflow 3 deprecates the plain file store. |
| 2026-11-25 | No licence file was added. | Choosing a licence is the repository owner's decision. |
| 2026-11-25 | The participant table may be `participants.tsv` (BIDS) or the V3 release's `TDBRAIN_participants_V3.xlsx`, searched in the data folder and its parent; macOS `._*` and Excel `~$*` files are ignored. `TDBRAIN_PATH` points at the folder holding `sub-*/` (e.g. `TDBRAIN_Dataset_V3_1`). | The user's copy is the V3 release, which ships the participant list as Excel next to the dataset folder. |
| 2026-11-25 | Phase-0 checkpoint: the user asked to proceed straight to training without reviewing counts. Defaults used: T1 (MDD vs HEALTHY) primary, T2 (MDD vs other diagnosed patients) secondary, adults 18–65, comorbid MDD kept (flagged), primary indication from `indication`, comorbidity from `indication` ∪ `formal_status`. Sex code mapping (0/1) still unconfirmed: reported as raw codes. | User instruction ("just do the required training"). |

Only `TDBRAIN_participants_V3.xlsx` and the restEC files were extracted from the archive by HTTP range requests (6.6 GB of 18.6 GB) into the git-ignored `data/tdbrain/`. | CLAUDE.md §2.1: private copy only; fetch only what is needed. |

Every run is tagged `overlay`. | 4 CPUs, no GPU: the full spec (EEGNet 3 seeds × 100 epochs, 16 shadows × 4 ε) would take more than a day. |
